## 한 줄 요약

보관된 Spaceship Titanic 분류 노트북을 다시 검토해 기본 전처리와 Random Forest 실행 기록을 정리했다. 저장된 학습 데이터 평가값을 성과로 과장하지 않고, 미실행 확장 실험과 전처리·검증 절차의 한계를 함께 기록한다.

## 프로젝트 범위와 데이터

이 글은 [Kaggle Spaceship Titanic](https://www.kaggle.com/competitions/spaceship-titanic) 데이터로 작성된 `space_titanic.ipynb`의 구현·실행 기록을 검토한 결과다. 노트북에 저장된 출력에서 학습 데이터는 8,693행, 예측 대상 데이터는 4,277행으로 확인했다.

| 항목      | 확인한 내용                                                                            |
| --------- | -------------------------------------------------------------------------------------- |
| 문제 유형 | 승객 이송 여부(`Transported`)를 예측하는 이진 분류                                     |
| 분석 대상 | 보관된 `space_titanic.ipynb`의 저장된 코드와 실행 출력                                 |
| 구현 상태 | 기본 전처리, Random Forest 학습, 학습 데이터 평가, 제출 CSV 생성 코드의 실행 기록 확인 |
| 공개 상태 | 초안. 깨끗한 환경에서의 재실행과 공개 품질 검토 전                                     |

노트북과 보관된 산출물만으로는 작성자 역할, Kaggle 리더보드 점수, 제출 여부를 확인할 수 없으므로 이 글에서는 주장하지 않는다.

## 노트북에서 확인한 전처리와 모델 구현

기본 실행 경로에서는 객실(`Cabin`)을 최빈값으로 보완한 뒤 `Deck`, `Num`, `Side`로 분리했다. 이 가운데 `Deck`과 `Side`는 원-핫 인코딩해 입력 특징으로 사용했고, `Num`은 최종 입력에서 제외했다.

| 처리 항목   | 저장된 구현                                                                 |
| ----------- | --------------------------------------------------------------------------- |
| `CryoSleep` | `True`/`False`를 1/0으로 변환한 뒤 최빈값으로 결측 보완                     |
| `VIP`       | `True`/`False`를 1/0으로 변환한 뒤 최빈값으로 결측 보완                     |
| `Age`       | 중앙값으로 결측 보완                                                        |
| 객실 위치   | `Cabin`에서 `Deck`, `Num`, `Side` 분리 후 `Deck`, `Side` 원-핫 인코딩       |
| 학습 특징   | `CryoSleep_fill`, `Deck`, `Side`, `Age_fill`, `VIP_fill`로 구성한 13개 특징 |
| 모델        | `RandomForestClassifier(n_estimators=100, random_state=42)`                 |

학습 데이터와 예측 대상 데이터의 전처리는 각각 수행했다. 따라서 이 노트북은 현재 경로에 바로 재현 가능한 실행 파일이 아니다. 원본 데이터 경로가 특정 개인 환경의 절대 경로로 고정돼 있어, 재실행 시 프로젝트 내부의 상대 경로로 바꿔야 한다.

## 저장된 실행 기록

기본 모델과 시각화 셀에는 실행 카운트와 출력이 남아 있다. 다음 수치는 학습에 사용한 동일한 8,693행을 다시 예측한 값이므로, 홀드아웃 검증이나 교차 검증 성능이 아니다.

| 항목         | 저장된 값 | 해석 범위             |
| ------------ | --------: | --------------------- |
| 정확도       |    0.7763 | 학습 데이터 자체 평가 |
| 가중 정밀도  |    0.7825 | 학습 데이터 자체 평가 |
| 가중 재현율  |    0.7763 | 학습 데이터 자체 평가 |
| 가중 F1 점수 |    0.7752 | 학습 데이터 자체 평가 |

노트북은 `PassengerId`, `Transported` 두 열로 제출 CSV를 만드는 코드를 포함하고, 같은 이름의 `submission.csv` 산출물도 보관한다. 다만 제출 파일이 어떤 실행 상태와 연결되는지, 외부에 실제 제출됐는지는 확인할 수 없다.

기본 실행 뒤에는 `CryoSleep` 상태별 이송률, `Deck`별 이송률, 특징 중요도, 혼동 행렬을 생성한 기록이 남아 있다. 예를 들어 저장된 집계 출력은 `CryoSleep=False` 5,439명 중 이송률 32.9%, `CryoSleep=True` 3,037명 중 이송률 81.8%를 보여 준다. 이는 해당 학습 데이터에서의 관찰이며 인과관계나 외부 데이터에서의 재현성을 뜻하지 않는다.

## 검증 한계와 재실행 기준

### 확인한 한계

- 시설 비용 특징, 5겹 계층화 교차 검증, Logistic Regression·Random Forest·XGBoost 비교를 선언한 뒤쪽 셀에는 실행 카운트와 출력이 없다. README의 모델 비교 결과와 Kaggle 점수는 이 글의 근거로 사용하지 않는다.
- 결측치 대체 통계와 원-핫 인코딩을 전체 학습 데이터에서 먼저 만든 뒤, 뒤쪽 미실행 셀이 교차 검증을 수행하도록 작성돼 있다. 그대로 실행하면 검증 폴드의 정보가 전처리 통계에 반영될 가능성이 있다.
- 현재 저장된 정확도와 혼동 행렬은 모델 학습에 쓴 데이터로 계산했다. 과적합 여부나 일반화 성능을 판단할 수 없다.
- 원본 시각화에는 한글 글리프 누락 경고가 남아 있고, 보관된 PNG에서도 한글이 사각형으로 깨진다. 이 글에는 해당 이미지를 사용하지 않는다.
- 노트북 앞부분의 기본 실행 셀과 이후 확장 실험 셀의 실행 상태가 일치하지 않는다. 기본 실행 결과와 확장 실험의 계획을 하나의 완료된 실험으로 묶어 해석할 수 없다.

### 다음 재실행에서의 기준

다음 실행에서는 결측치 처리, 범주형 인코딩, 특징 생성을 `Pipeline` 또는 사용자 정의 변환기로 묶고 각 교차 검증 학습 폴드에서만 `fit`해야 한다. scikit-learn은 파이프라인이 교차 검증에서 테스트 데이터의 통계가 학습 과정에 유입되는 문제를 줄이는 데 도움을 준다고 안내한다([공식 문서](https://scikit-learn.org/stable/modules/compose.html)).

또한 깨끗한 커널에서 모든 셀을 순서대로 실행하고, 패키지 버전·분할 방식·평가값·최종 제출 파일 생성 모델을 함께 남긴다. 공개용 그래프는 한글 글꼴을 명시적으로 설정한 뒤 다시 생성해야 한다.

## 배운 점

모델 코드가 존재하는 것과 검증된 실험 결과가 존재하는 것은 다르다. 전처리 통계를 학습 폴드 안에서 계산하고, 실제 실행한 모델·평가 방식·제출 산출물의 연결을 남겨야 나중에 결과를 다시 검증할 수 있다.
