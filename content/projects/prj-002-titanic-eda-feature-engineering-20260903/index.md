## 한 줄 요약

보관된 Titanic 분류 노트북을 다시 검토해 탐색적 분석(EDA), 특징 공학, 교차 검증 결과를 정리했다. 저장된 실행값을 성과로 과장하지 않고, 전처리 시점과 노트북 실행 상태가 재현성에 주는 한계도 함께 기록한다.

## 프로젝트 범위와 데이터

이 글은 [Kaggle Titanic - Machine Learning from Disaster](https://www.kaggle.com/competitions/titanic) 데이터로 작성된 노트북의 구현·실행 기록을 검토한 결과다. 원본 노트북에서 확인한 학습 데이터는 891행 12열, 예측 대상 테스트 데이터는 418행 11열이다.

| 항목      | 확인한 내용                                                |
| --------- | ---------------------------------------------------------- |
| 문제 유형 | 생존 여부를 예측하는 이진 분류                             |
| 분석 대상 | 보관된 `titanic_portfolio.ipynb`의 실행 기록               |
| 구현 상태 | EDA, 특징 생성, 로지스틱 회귀·랜덤 포레스트 실행 기록 확인 |
| 공개 상태 | 초안. 재현 실행과 공개 품질 검토 전                        |

노트북 자체로 작성자 역할이나 Kaggle 리더보드 점수는 확인할 수 없으므로, 이 글에서는 이를 주장하지 않는다.

## 탐색적 분석에서 확인한 관찰

학습 데이터의 전체 생존율은 38.4%였다. 아래 값은 노트북에 저장된 집계 출력이며, 각 특징과 생존의 **상관관계**를 보여 줄 뿐 원인이나 역사적 맥락을 증명하지 않는다.

| 구분  | 생존율 | 표본 수 |
| ----- | -----: | ------: |
| 여성  |  74.2% |     314 |
| 남성  |  18.9% |     577 |
| 1등석 |  63.0% |     216 |
| 2등석 |  47.3% |     184 |
| 3등석 |  24.2% |     491 |

`SibSp + Parch + 1`로 계산한 가족 규모에서도 차이가 관찰됐다. 다만 일부 규모의 표본 수가 작으므로, 가족 규모 하나만으로 일반화하지 않았다.

데이터 품질 측면에서는 `Age` 177건(19.9%), `Cabin` 687건(77.1%), `Embarked` 2건의 결측이 확인됐다. 특히 `Cabin`은 결측 비율이 높아 모델 입력 특징에서 제외했다.

## 전처리와 특징 공학

노트북은 `Sex`를 수치로 변환하고, `Pclass`와 `Sex`별 중앙값으로 `Age`를 채웠다. 이후 가족 규모, 단독 승객 여부, 가족 범주, 아동 여부를 만들었다.

| 모델 입력 특징   | 생성 또는 처리 방식                                           |
| ---------------- | ------------------------------------------------------------- |
| `Pclass`, `Fare` | 원본 수치 특징. 테스트 데이터의 `Fare` 결측은 중앙값으로 처리 |
| `Sex_encoded`    | 남성 0, 여성 1로 변환                                         |
| `Age_filled`     | `Pclass`, `Sex` 그룹의 중앙값으로 `Age` 결측 보완             |
| `FamilySize`     | `SibSp + Parch + 1`                                           |
| `IsAlone`        | 가족 규모가 1명인지 여부                                      |
| `FamilyCategory` | 가족 규모를 범주화                                            |
| `IsChild`        | 아동 여부                                                     |

`IsAdult`도 생성했지만 최종 모델 입력 특징에는 포함하지 않았다.

## 저장된 로컬 실행 결과

다음은 노트북에 남아 있는 5겹 교차 검증 실행 출력이다. 같은 노트북의 전처리 순서에 한계가 있으므로, 새로 재현한 성능이나 외부 평가 결과가 아니라 **저장된 로컬 실행 기록**으로만 해석한다.

| 모델                    | 설정                                                  | 정확도 평균 | 표준편차 |
| ----------------------- | ----------------------------------------------------- | ----------: | -------: |
| 로지스틱 회귀           | 기본 설정                                             |      0.8047 |   0.0163 |
| 랜덤 포레스트           | `n_estimators=100`, `random_state=42`                 |      0.8160 |   0.0279 |
| 랜덤 포레스트 격자 탐색 | `n_estimators`, `max_depth`, `min_samples_split` 탐색 |      0.8395 |        - |

격자 탐색에서 저장된 최적 조합은 `n_estimators=200`, `max_depth=None`, `min_samples_split=10`이었다. 제출 파일은 418행이고 예측 결측이 0건인 형식 검증 기록만 확인했다. 이 파일의 생성 모델 상태는 노트북만으로 확정할 수 없으므로, 예측 성능 근거로 사용하지 않는다.

## 검증 한계와 재실행 설계

### 확인한 한계

- `Age_filled`의 그룹별 중앙값을 교차 검증 이전에 학습 데이터 전체로 계산했다. 검증 폴드의 특성이 전처리 통계에 반영될 수 있으므로, 교차 검증 점수를 엄격한 일반화 성능으로 해석할 수 없다.
- XGBoost 격자 탐색과 모델 비교 셀에는 실행 출력이 남아 있지 않다. 따라서 XGBoost 비교나 최종 모델 선택 결과는 기록하지 않는다.
- 특징 중요도와 혼동 행렬 출력은 남아 있지만, 직전 셀의 `best_model` 정의와 실행 순서가 일관되지 않아 현재 소스 기준으로 재현 가능한 결과라고 보기 어렵다.
- README에 적힌 Kaggle 점수는 로컬 산출물이나 리더보드 근거로 확인하지 못했다.
- 기존 그래프는 한글 글꼴이 깨져 공개 문서에 사용하지 않았다.

### 다음 재실행에서의 기준

다음 실행에서는 결측치 처리와 특징 생성을 `Pipeline` 또는 사용자 정의 변환기로 묶어 각 학습 폴드에서만 `fit`되게 해야 한다. scikit-learn은 파이프라인이 교차 검증에서 테스트 데이터의 통계가 학습 과정에 유입되는 문제를 막는 데 도움을 준다고 안내한다([공식 문서](https://scikit-learn.org/stable/modules/compose.html)).

또한 깨끗한 커널에서 모든 셀을 처음부터 실행하고, 패키지 버전·분할 설정·평가 결과·제출 파일 생성 모델을 함께 저장한다. 공개용 그래프는 한글 글꼴을 검증한 뒤 새로 만든다.

## 배운 점

이 기록에서 중요한 결과는 특정 정확도 하나가 아니다. 특징을 만든 시점, 각 모델을 실제로 실행한 근거, 제출 파일과 모델의 연결을 남겨야 나중에 같은 결론을 재검증할 수 있다. 다음 실습에서는 전처리와 평가 절차를 하나의 재현 가능한 실험 단위로 관리한다.
